## Задача 1. Two sum

### Описание

Функция two_sum проходит по массиву слева направо и хранит в словаре
index_by_value уже встреченные значения и их индексы. Для текущего значения
current_value вычисляется дополнение required_value = k - current_value.
Если дополнение уже встречалось, его индекс и текущий индекс образуют ответ.

Проверка выполняется до добавления текущего элемента в словарь. Поэтому один
элемент нельзя использовать дважды, но два равных элемента с разными индексами
обрабатываются правильно. Сохранённый индекс всегда меньше текущего, поэтому
ответ сразу возвращается в порядке возрастания.

### Оценка сложности

**Сложность:** среднее время - O(n), так как массив просматривается один раз,
а поиск и вставка в словарь в среднем занимают O(1). Дополнительная память -
O(n) для словаря встреченных элементов.

### Визуализация

Визуализация для arr = [1, 3, 4, 10], k = 7:

| Индекс | Текущее значение | Ищем значение | Уже встреченные | Результат |
|---:|---:|---:|---|---|
| 0 | 1 | 6 | {} | сохраняем 1: 0 |
| 1 | 3 | 4 | {1: 0} | сохраняем 3: 1 |
| 2 | 4 | 3 | {1: 0, 3: 1} | значение 3 найдено |

Получаем индексы (1, 2): arr[1] + arr[2] = 3 + 4 = 7.

### Тесты

Файл two_sum/test_two_sum.py проверяет самостоятельные наборы данных, которые
не повторяют примеры из условия: пару в середине массива, одинаковые значения,
отрицательные числа, нули, пару на границах и отсутствие подходящей пары.

Запуск программы из корня репозитория:

```bash
python -m homework_3.two_sum.two_sum
```

После запуска нужно ввести массив целых чисел в одной строке через пробел, а
затем искомую сумму в следующей строке.

## Задача 2. Anagrams

### Описание

У всех анаграмм после сортировки символов получается одинаковая сигнатура.
Например, слова eat, tea и ate получают сигнатуру ('a', 'e', 't').
Функция group_anagrams использует сигнатуру как ключ словаря, а значением
делает список всех слов с этой сигнатурой. Порядок слов внутри каждой группы и
порядок появления групп сохраняются такими же, как во входном списке.

Регистр учитывается: например, Tea и eat не считаются анаграммами, потому
что символы T и t различаются.

### Оценка сложности

Пусть n - количество слов, а m - максимальная длина слова. **Сложность:**
время - O(n * m log m), так как символы каждого слова сортируются;
дополнительная память - O(n * m) для сигнатур и сгруппированных слов.

### Визуализация

Визуализация для strs = ["eat", "tea", "tan", "ate", "nat", "bat"]:

| Слово | Сигнатура | Группа после добавления |
|---|---|---|
| eat | aet | [eat] |
| tea | aet | [eat, tea] |
| tan | ant | [tan] |
| ate | aet | [eat, tea, ate] |
| nat | ant | [tan, nat] |
| bat | abt | [bat] |

Итоговые группы: [[eat, tea, ate], [tan, nat], [bat]]. Порядок групп не
влияет на правильность ответа.

### Тесты

Файл anagrams/test_anagrams.py использует слова, отличные от примера в
условии, и проверяет несколько групп, пустой список, одно слово, пустые строки,
повторяющиеся буквы и учёт регистра.

Запуск программы из корня репозитория:

```bash
python -m homework_3.anagrams.anagrams
```

После запуска нужно ввести слова в одной строке через пробел.

## Задача 3. Создание хеш-таблицы

### Описание

Класс HashTable хранит массив корзин. Массив, каждая корзина и каждая пара
[ключ, значение] реализованы только с помощью list. Номер корзины
вычисляется как hash(key) % capacity.

Коллизии разрешаются методом цепочек: если разные ключи получили один индекс,
их пары добавляются в одну корзину. Поиск и удаление просматривают только эту
корзину и сравнивают ключи. Повторная вставка существующего ключа обновляет его
значение и не увеличивает размер таблицы.

Перед вставкой вычисляется будущий коэффициент заполнения. Если он превысит
max_load_factor (по умолчанию 0.75), количество корзин удваивается, а все
пары перераспределяются с учётом новой вместимости. Это не даёт цепочкам
неограниченно расти при равномерной хеш-функции.

Основные операции:

- insert(key, value) - вставка или обновление;
- search(key) - поиск значения;
- delete(key) - удаление и возврат значения.

Также реализованы len, оператор in, синтаксис table[key], свойства
capacity и load_factor, методы keys, values, items и clear.
Для отсутствующего ключа search и delete возбуждают KeyError. Ключи
должны быть хешируемыми, как и ключи встроенного dict.

### Оценка сложности

При равномерном распределении **средняя сложность** вставки, поиска и удаления
- O(1). В худшем случае, когда все ключи попали в одну корзину, каждая операция
занимает O(n). Расширение занимает O(n), но выполняется редко, поэтому
амортизированная стоимость вставки остаётся O(1). Дополнительная память - O(n).

### Визуализация

Пример таблицы с четырьмя корзинами после вставки трёх ключей, два из которых
получили одинаковый индекс:

```text
Индекс 0: []
Индекс 1: [["name", "Ada"], ["city", "London"]]  <- коллизия, одна цепочка
Индекс 2: []
Индекс 3: [["year", 1815]]
```

Поиск ключа city вычисляет индекс 1, затем последовательно сравнивает ключи
в этой корзине и возвращает London. При расширении до восьми корзин каждая
пара получает новый индекс по формуле hash(key) % 8.

### Тесты

Файл hash_table/test_hash_table.py проверяет вставку, поиск, обновление,
удаление, отсутствующие ключи, настоящие коллизии, автоматическое расширение с
сохранением 100 значений, дополнительный словарный интерфейс, очистку,
параметры конструктора, использование списков для хранения данных и работу
консольного меню с введёнными пользователем ключом и значением.

Запуск программы из корня репозитория:

```bash
python -m homework_3.hash_table.hash_table
```

После запуска отображается меню. С его помощью можно вводить с клавиатуры ключи
и значения, искать и удалять пары, просматривать содержимое таблицы. Команда 0
завершает программу. В консольном режиме ключи и значения читаются как строки;
сам класс HashTable поддерживает любые хешируемые типы ключей.
