# Домашнее задание 2

## Задача 1. Stack vs queue

### Описание

Обе структуры построены на односвязном списке из узлов Node, где каждый узел
хранит значение и ссылку на следующий узел.

Стек LinkedStac` работает по принципу LIFO. Новый элемент добавляется в голову
списка (push), и оттуда же извлекается последний добавленный элемент (pop).
Так как обе операции работают только с головой, они выполняются за константное
время без сдвига остальных узлов.

Очередь LinkedQueue работает по принципу FIFO. Она хранит ссылки и на голову,
и на хвост списка. Добавление (enqueue) идёт в хвост, а извлечение
(dequeue) - из головы. Отдельная ссылка на хвост позволяет добавлять элемент
за константное время. Когда очередь становится пустой, ссылка на хвост
сбрасывается вместе с головой.

Обе структуры хранят счётчик size, поэтому __len__ возвращает размер за
O(1). Извлечение или просмотр из пустой структуры возбуждает IndexError.

### Оценка сложности

**Сложность:** время - O(1) на каждую операцию push/pop, enqueue/dequeue,
peek, так как каждая операция работает с фиксированным числом узлов (голова
или хвост). Дополнительная память - O(n) на хранение n элементов; отдельная
операция дополнительной памяти не требует, O(1).

### Визуализация

Чередование операций для стека:

| Операция | Состояние стека (голова слева) | Результат |
|---|---|---|
| push(1) | 1 | - |
| push(2) | 2 1 | - |
| pop() | 1 | 2 |
| push(3) | 3 1 | - |
| pop() | 1 | 3 |
| pop() | (пусто) | 1 |

Те же операции для очереди:

| Операция | Состояние очереди (голова слева) | Результат |
|---|---|---|
| enqueue(1) | 1 | - |
| enqueue(2) | 1 2 | - |
| dequeue() | 2 | 1 |
| enqueue(3) | 2 3 | - |
| dequeue() | 3 | 2 |
| dequeue() | (пусто) | 3 |

Стек возвращает элементы в обратном порядке (LIFO), очередь - в порядке
добавления (FIFO).

### Тесты

Файл`stack_vs_queue/test_stack_vs_queue.py проверяет порядок LIFO для стека и
FIFO для очереди, работу peek без удаления, is_empty и __len__, ошибки при
операциях над пустыми структурами, чередование операций и повторное
использование очереди после опустошения.

Запуск программы из корня репозитория:

```bash
python -m homework_2.stack_vs_queue.stack_vs_queue
```

После запуска нужно ввести целые числа в одной строке через пробел и нажать
Enter. Программа прогонит их через стек (порядок LIFO) и через очередь (порядок
FIFO). Например: 1 2 3.

## Задача 2. Validate

### Описание

Функция validate_stack_sequences моделирует работу стека. Мы идём по
последовательности pushed и кладём каждый элемент во вспомогательный стек.
После каждого добавления мы жадно снимаем элементы с вершины, пока она совпадает
с текущим ожидаемым элементом popped[pop_index], сдвигая указатель pop_index.

Идея в том, что элемент можно снять только тогда, когда он находится на вершине.
Если после обработки всех элементов pushed вспомогательный стек пуст, значит
все элементы удалось снять в порядке popped, и последовательность корректна.
Если же в стеке остались элементы, требуемый порядок pop невозможен.

### Оценка сложности

**Сложность:** время - O(n), где n - длина последовательностей. Каждый элемент
кладётся в стек и снимается ровно один раз. Дополнительная память - O(n) на
вспомогательный стек в худшем случае.

### Визуализация

Визуализация для pushed = [1, 2, 3, 4, 5], popped = [1, 3, 5, 4, 2]:

| Шаг | push | Стек после push | Снимаем | Стек после pop | popped-указатель |
|---|---|---|---|---|---|
| 1 | 1 | 1 | 1 | (пусто) | указывает на 3 |
| 2 | 2 | 2 | - | 2 | указывает на 3 |
| 3 | 3 | 2 3 | 3 | 2 | указывает на 5 |
| 4 | 4 | 2 4 | - | 2 4 | указывает на 5 |
| 5 | 5 | 2 4 5 | 5, 4, 2 | (пусто) | вышли за конец |

Стек пуст в конце, поэтому результат True.

Для pushed = [1, 2, 3], popped = [3, 1, 2] после push(1), push(2), push(3)
снимается 3, но затем ожидается 1, а на вершине лежит 2. Снять ничего нельзя,
стек остаётся непустым, поэтому результат False.

### Тесты

Файл validate/test_validate.py проверяет оба примера из условия, случай с одним
элементом, совпадающий порядок, полный разворот, невозможную перестановку и
крупный вход на 100 000 элементов.

Запуск программы из корня репозитория:

```bash
python -m homework_2.validate.validate
```

После запуска нужно ввести две строки: сначала последовательность pushed, затем
popped, каждую через пробел.

## Задача 3. Merge lists

### Описание

Оба способа сливают два отсортированных списка, каждый раз выбирая узел с меньшим
значением и присоединяя его к результату. Так как исходные списки уже
отсортированы, достаточно одного прохода: на каждом шаге сравниваются головы
двух списков. Когда один список заканчивается, к результату присоединяется
остаток другого. Узлы переиспользуются, новые не создаются.

Способ с фиктивным элементом merge_with_dummy создаёт вспомогательный узел
dummy, к которому пристраивается результат. Это избавляет от отдельной
обработки первого узла: голова результата - это dummy.next.

Способ без фиктивного элемента merge_without_dummy сначала явно выбирает голову
результата (меньшую из двух голов), а затем достраивает остаток тем же циклом.
Дополнительно обрабатываются случаи, когда один из списков пуст.

### Оценка сложности

**Сложность:** время - O(n + m), где n и m - длины списков, так как каждый узел
просматривается один раз. Дополнительная память - O(1): узлы переиспользуются,
а фиктивный элемент занимает константную память.

### Визуализация

Визуализация для list1 = [1, 2, 4], list2 = [1, 3, 4] (способ с фиктивным
элементом):

| Шаг | Голова list1 | Голова list2 | Выбрали | Результат |
|---|---|---|---|---|
| 1 | 1 | 1 | 1 (из list1) | 1 |
| 2 | 2 | 1 | 1 (из list2) | 1 1 |
| 3 | 2 | 3 | 2 (из list1) | 1 1 2 |
| 4 | 4 | 3 | 3 (из list2) | 1 1 2 3 |
| 5 | 4 | 4 | 4 (из list1) | 1 1 2 3 4 |
| 6 | (пусто) | 4 | остаток list2 | 1 1 2 3 4 4 |

Итог: [1, 1, 2, 3, 4, 4].

### Тесты

Файл merge_lists/test_merge_lists.py проверяет обе реализации на одном наборе
случаев через subTest: пример из условия, два пустых списка, один пустой,
списки разной длины, дубликаты и непересекающиеся диапазоны.

Запуск программы из корня репозитория:

```bash
python -m homework_2.merge_lists.merge_lists
```

После запуска нужно ввести два отсортированных списка: сначала первый, затем
второй, каждый в одной строке через пробел. Программа выведет результат слияния
обеими реализациями. Например: 1 2 4, затем 1 3 4.
