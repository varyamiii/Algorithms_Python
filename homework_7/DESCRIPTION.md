# Домашнее задание 7. Куча

Все функции работают с целыми числами. Функции построения кучи и `heapsort`
изменяют переданный список на месте и возвращают ссылку на него. В реализации

## Задача 1. Makeheap

### Описание решения

Для элемента с индексом `i` дети находятся по индексам `2i + 1` и `2i + 2`.
В minheap родитель не больше каждого ребёнка.

`makeheap_n_log_n` рассматривает очередной элемент как добавленный в конец
уже готовой кучи и поднимает его, пока он меньше родителя. `makeheap` проходит
внутренние узлы справа налево и опускает каждый в уже готовых кучах его детей.
Листья заранее являются кучами из одного элемента.

Пример `makeheap([9, 4, 7, 1, 5, 3])`:

| Обработанный индекс | Состояние массива |
|---:|---|
| начало | `[9, 4, 7, 1, 5, 3]` |
| 2 | `[9, 4, 3, 1, 5, 7]` |
| 1 | `[9, 1, 3, 4, 5, 7]` |
| 0 | `[1, 4, 3, 9, 5, 7]` |

### Доказательство сложности

При последовательной вставке элемент с индексом `i` поднимается не более чем
на `⌊log₂(i + 1)⌋` уровней. Следовательно, в худшем случае
`T(n) = O(Σᵢ₌₁ⁿ⁻¹ log(i + 1)) = O(n log n)`. На убывающем входе почти каждый
новый элемент поднимается до корня, так что худшая оценка — `Θ(n log n)`.

Для сборки снизу вверх пусть `height(i)` — высота поддерева узла `i`.
Опускание этого узла стоит `O(1 + height(i))`. Узел имеет высоту не меньше `h`
только если в его поддереве есть потомок на глубине `h`. В полном по уровням
дереве массива тогда существует и самый левый потомок с индексом
`2ʰi + (2ʰ − 1) < n`. Поэтому таких узлов не более `⌊n / 2ʰ⌋`.
Переставим порядок суммирования высот:

```text
Σᵢ height(i)
  = Σₕ₌₁^⌊log₂ n⌋ #{i : height(i) ≥ h}
  ≤ Σₕ₌₁^⌊log₂ n⌋ ⌊n / 2ʰ⌋
  ≤ n Σₕ₌₁^∞ (1/2)ʰ
  = n.
```

Цикл вызывает опускание для `⌊n/2⌋` внутренних узлов; постоянная работа на
каждом и сумма высот дают **O(n)** времени. В худшем случае нужно обработать
`Θ(n)` внутренних узлов, поэтому оценка — **Θ(n)**. Оба метода используют
**O(1)** дополнительной памяти: перестановки выполняются в исходном списке,
рекурсии нет.

входного массива и проверка результата вне измеряемого участка. Случайные
числа в диапазоне от −1 000 000 до 1 000 000, seed 42. Время в мс.

|---|---:|---:|---:|
| Случайный | 1 000 | 0,124 | 0,143 |
| Случайный | 5 000 | 0,719 | 0,728 |

| Убывающий | 20 000 | 16,039 | 3,207 |

На случайном входе ранняя остановка при подъёме делает методы близкими по

## Задача 2. K-th minheap

### Описание решения

По примерам требуется **k-й наибольший** элемент, причём повторы занимают
отдельные позиции. Обе реализации хранят в minheap ровно `k` наибольших
значений из уже просмотренного префикса. Корень — наименьший среди них.
Если очередное значение больше корня, оно заменяет корень, и куча
восстанавливается опусканием. Иначе значение не может попасть в верхние `k`.
После просмотра всего массива корень и есть ответ.

`k_th_largest` использует собственные `makeheap` и `_sift_down`;
`k_th_largest_heapq` выполняет те же действия через `heapq.heapify` и
`heapq.heapreplace`. Входной массив не изменяется. При `k` вне диапазона
`1..len(nums)` обе функции выбрасывают `ValueError`.

Пример для `nums = [3, 2, 1, 5, 6, 4]`, `k = 2`:

| Шаг | Куча двух наибольших | Действие |
|---|---|---|
| первые два числа | `[2, 3]` | построили minheap |
| 1 | `[2, 3]` | 1 ≤ 2, пропускаем |
| 5 | `[3, 5]` | заменили корень |
| 6 | `[5, 6]` | заменили корень |
| 4 | `[5, 6]` | 4 ≤ 5, пропускаем |

Ответ — `5`. Построение начальной кучи требует `O(k)` времени. Для каждого
из оставшихся `n-k` элементов проверка стоит `O(1)`, а возможная замена —
`O(log k)`. Итого в худшем случае **O(n + (n-k) log(k+1))** времени и
**O(k)** дополнительной памяти для обеих реализаций. При `k = 1` и при
`k = n` время линейно. Сортировка всего массива не выполняется.

## Задача 3. Heapsort

### Описание решения

Для сортировки по возрастанию строится **maxheap**: максимум находится в корне.
Он меняется местами с последним элементом активной кучи. Этот элемент уже на
окончательном месте. Активная куча сокращается на один элемент, а новый корень
опускается вниз. После повторения весь массив отсортирован.

Для `[4, 1, 3, 2]` сначала получается maxheap `[4, 2, 3, 1]`:

| После извлечения максимума | Активная куча | Готовый суффикс |
|---:|---|---|
| 4 | `[3, 2, 1]` | `[4]` |
| 3 | `[2, 1]` | `[3, 4]` |
| 2 | `[1]` | `[2, 3, 4]` |

Построение maxheap снизу вверх занимает **O(n)** по тому же доказательству,
что и построение minheap. Затем идут `n-1` опусканий глубиной не больше
`O(log n)`. Время в худшем случае — **O(n log n)**, дополнительная память —
**O(1)**: используются только индексы и обмены внутри входного массива.
`sorted()`, `list.sort()` и `heapq` в реализации heapsort не используются.

### Сравнение производительности

Для всех алгоритмов использованы одинаковые случайные входы и тот же порядок
измерений, что выше. Для `mergesort` взята собственная
`merge_sort_recursive` из `homework_6/compare/compare.py`. Она возвращает
новый список; остальные результаты тоже проверяются вне измеряемого участка.
Время в мс.

| n | `heapsort` | `sorted()` | `merge_sort_recursive` |
|---:|---:|---:|---:|
| 1 000 | 1,077 | 0,049 | 0,927 |
| 5 000 | 6,983 | 0,372 | 5,712 |
| 20 000 | 33,220 | 1,853 | 25,960 |

На этих входах встроенная сортировка быстрее обеих реализаций на Python.
Сортировка слиянием также оказалась быстрее heapsort, хотя обе имеют
асимптотику `O(n log n)` по времени. Преимущество heapsort здесь —
`O(1)` дополнительной памяти при сортировке на месте; реализация
`merge_sort_recursive` создаёт списки и использует `O(n)` дополнительной
памяти.
