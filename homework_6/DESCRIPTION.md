# Домашнее задание 6

Все функции принимают список целых чисел, возвращают новый результат и не
изменяют входной список. Сортировка идёт по возрастанию. Тесты написаны на
`unittest`, как в `homework_5`.

## Задача 1. Compare

### Корректность и идея решения

`merge_sort_recursive` делит массив пополам, рекурсивно сортирует обе половины
и сливает их, каждый раз выбирая меньший из первых элементов. При равенстве
берётся элемент слева, поэтому слияние стабильно. База — массив длины 0 или 1.

`quick_sort_recursive` копирует массив, ставит последний элемент диапазона на
свою окончательную позицию разделением Ломуто и рекурсивно обрабатывает меньшую
часть. Большую часть обрабатывает тот же вызов в цикле. Слева от опорного
остаются элементы `<=` него, справа — элементы `>` него. Это сохраняет
рекурсивную идею quicksort и не переполняет стек на длинном отсортированном
массиве.

`measure_time` использует `perf_counter`, печатает время даже при исключении,
сохраняет результат и метаданные функции через `wraps`. Декоратор применён к
внешним вызовам обеих сортировок, поэтому измеряется вся сортировка, а не
отдельные рекурсивные шаги.

### Оценка сложности

| Метод | Время | Дополнительная память | Причина |
| --- | --- | --- | --- |
| Merge sort | O(n log n) всегда | O(n) | log n уровней, на каждом слияние всех n элементов; списки и результат суммарно занимают O(n) на пике |
| Quicksort | O(n log n) в среднем, O(n²) в худшем случае | O(log n) стек в худшем случае + O(n) копия входа | Разделение O(n), глубина рекурсии ограничена обработкой меньшей части |
| Декоратор | O(1) поверх измеряемого вызова | O(1) | Два отсчёта часов и одна строка вывода |

Последний элемент как опорный делает уже отсортированный массив худшим случаем
quicksort: каждый раз отделяется только один элемент. Это позволяет показать
существенное различие времени без случайных данных. Для `list(range(600))`
merge sort выполняет примерно `600 log₂ 600` операций слияния, а quicksort —
`600·599/2` сравнений при разделении. Фактическое время зависит от машины;
демонстрация печатает оба результата, а тесты не требуют конкретного отношения
времён, чтобы не зависеть от нагрузки системы.

### Пошаговая визуализация

Для `[4, 1, 3, 2]` merge sort:

```text
[4, 1, 3, 2]
→ [4, 1] | [3, 2]
→ [4] | [1] | [3] | [2]
→ [1, 4] | [2, 3]
→ [1, 2, 3, 4]
```

Для того же массива quicksort (опорный элемент каждого диапазона — последний):

```text
[4, 1, 3, 2], pivot=2 → [1] 2 [3, 4]
[3, 4], pivot=4    → [3] 4 []
Итог                → [1, 2, 3, 4]
```

### Тесты и запуск

`compare/test_compare.py` проверяет оба алгоритма на пустом, одиночном,
упорядоченном, обратном, повторяющемся и смешанном входе, неизменность данных,
длинный массив, вывод декоратора, возврат результата, исключение и метаданные.

```bash
python -m homework_6.compare.compare
python -m unittest discover -s homework_6/compare -p "test_*.py" -v
```

## Задача 2. Iterative

### Корректность и идея решения

`merge_sort_iterative` сначала считает каждый элемент отсортированным блоком
длины 1. На проходе с шириной `w` сливает соседние блоки этой длины во второй
буфер, затем меняет буферы местами и удваивает `w`. После последнего прохода
весь массив — один отсортированный блок.

`quick_sort_iterative` использует то же разделение Ломуто, что и рекурсивная
версия. Необработанные диапазоны хранит в явном стеке. Меньший диапазон
обрабатывается сразу, больший откладывается; поэтому размер стека ограничен
O(log n). Диапазоны длины 0 и 1 уже отсортированы.

### Оценка сложности

| Метод | Время | Дополнительная память | Причина |
| --- | --- | --- | --- |
| Merge sort | O(n log n) | O(n) | log n проходов по n элементам, два буфера |
| Quicksort | O(n log n) в среднем, O(n²) в худшем случае | O(n) копия + O(log n) стек | Разделение O(n), в худшем случае опорный каждый раз крайний |

### Пошаговая визуализация

Для `[4, 1, 3, 2]` итеративный merge sort:

```text
Ширина 1: [4] [1] [3] [2] → [1, 4] [2, 3]
Ширина 2: [1, 4] [2, 3]   → [1, 2, 3, 4]
```

Для того же массива итеративный quicksort:

```text
Стек: [(0, 3)], массив: [4, 1, 3, 2]
Разделение по 2: [1, 2, 3, 4], позиция 1; справа диапазон (2, 3)
Разделение по 4: [1, 2, 3, 4], позиция 3; диапазонов не осталось
```

### Тесты и запуск

`iterative/test_iterative.py` проверяет типичные, граничные, случайные с
фиксированным seed, длинный отсортированный массив и неизменность входа.

```bash
python -m homework_6.iterative.iterative
python -m unittest discover -s homework_6/iterative -p "test_*.py" -v
```

## Задача 3. K-th

### Корректность и идея решения

`find_kth_largest(nums, k)` ищет индекс `len(nums) - k` в порядке возрастания.
Quickselect выбирает опорный элемент из середины текущего диапазона и за один
проход разбивает его на значения меньше, равные и больше опорного. Если целевой
индекс попал в среднюю группу, ответ найден; иначе продолжается только в одной
нужной части. Массив целиком не сортируется, куча не используется. Повторы
учитываются как отдельные позиции. Для недопустимого `k` вызывается
`ValueError`, вход остаётся неизменным.

### Оценка сложности

В среднем O(n) времени: на каждом шаге рассматривается только одна часть.
При неудачном выборе опорных элементов худшее время O(n²). Копия входа требует
O(n) памяти; итеративный алгоритм поверх неё использует O(1) памяти.

### Пошаговая визуализация

`nums = [3, 2, 1, 5, 6, 4]`, `k = 2`, целевой индекс `6 - 2 = 4`:

```text
Диапазон [0..5], pivot=1 → [ ] [1] [3, 2, 5, 6, 4]
Индекс 4 справа; продолжаем в [1..5].
pivot=6 → [2, 5, 4, 3] [6] [ ]; индекс 4 слева.
pivot=5 → [2, 4, 3] [5] [ ]; индекс 4 попал в группу [5]. Ответ: 5.
```

В схеме порядок внутри групп не важен; реализация меняет элементы местами.

### Тесты и запуск

`k_th/test_k_th.py` проверяет оба примера, границы `k`, одинаковые и
отрицательные значения, дубликаты, недопустимые аргументы, все ранги на
детерминированных наборах и сохранность входа.

```bash
python -m homework_6.k_th.k_th
python -m unittest discover -s homework_6/k_th -p "test_*.py" -v
```
