## Задача 1. Tracer

### Корректность и идея решения

Декоратор `trace` оборачивает вызов функции, печатает строку входа `->`,
увеличивает текущую глубину стека и после завершения печатает строку возврата
`<-` вместе с результатом. Глубина хранится в `ContextVar`, поэтому она
корректно восстанавливается после каждого вызова и не смешивается между
параллельными контекстами. Блок `finally` восстанавливает глубину даже при
исключении; само исключение отмечается маркером `!!` и передаётся вызывающему
коду без изменения. `functools.wraps` сохраняет имя и документацию функции.
ASCII-маркеры корректно отображаются в том числе в Windows-консоли CP1251.

Доступны обе формы записи: `@trace` и `@trace(stream=output, indent="....")`.

### Оценка сложности

Помимо самой декорированной функции, один вызов требует O(1) служебной памяти
и O(a + r) времени на формирование строк, где a — размер представления
аргументов, r — размер представления результата. Для рекурсии глубины d
декоратор занимает O(d) памяти вместе со стеком вызовов. Вывод всех строк также
занимает O(d) операций вывода на одной нисходящей и восходящей ветви.

### Визуализация

Для `factorial(3)` декоратор выводит:

```text
-> factorial(3)
  -> factorial(2)
    -> factorial(1)
    <- factorial = 1
  <- factorial = 2
<- factorial = 6
```

Отступ показывает глубину стека, а парные стрелки — вход и возврат.

### Тесты и запуск

`tracer/test_tracer.py` проверяет рекурсивные отступы и результаты, именованные
аргументы, настраиваемый отступ, обработку исключения, восстановление глубины,
текущий `stdout` и сохранение метаданных функции.

```bash
python -m homework_5.tracer.tracer
python -m unittest discover -s homework_5/tracer -p "test_*.py" -v
```

## Задача 2. Permutations

### Корректность и идея решения

На каждом уровне рекурсии функция выбирает очередной элемент, удаляет его из
набора оставшихся и добавляет его перед каждой перестановкой остатка. База
рекурсии — пустой остаток, у которого существует одна перестановка: пустой
список. Поэтому каждая ветвь выбирает ровно n элементов и создаёт одну полную
перестановку. Множество `used_at_this_depth` не позволяет одинаковому значению
создать одинаковые ветви, поэтому результат уникален и для входа с повторами.
Исходный массив преобразуется в кортеж и не изменяется.

При `visualize=True` рекурсивная функция оборачивается декоратором `trace` из
первой задачи. По умолчанию визуализация выключена, чтобы функция могла
использоваться без побочного вывода.

### Оценка сложности

Для n различных элементов существует n! результатов длины n, поэтому время —
O(n · n!), а память результата — O(n · n!). Глубина рекурсии равна O(n);
созданные на пути кортежи требуют O(n²) вспомогательной памяти. Без учёта
результата рекурсивная рабочая память равна O(n²). При повторах ветвей меньше.

### Пошаговая визуализация

Для `[1, 2, 3]` верхние уровни дерева решений выглядят так:

```text
[]
├── 1 → [1]
│   ├── 2 → [1, 2] → [1, 2, 3]
│   └── 3 → [1, 3] → [1, 3, 2]
├── 2 → [2]
│   ├── 1 → [2, 1] → [2, 1, 3]
│   └── 3 → [2, 3] → [2, 3, 1]
└── 3 → [3]
    ├── 1 → [3, 1] → [3, 1, 2]
    └── 2 → [3, 2] → [3, 2, 1]
```

Фрагмент реального вывода декоратора:

```text
-> build_permutations((1, 2))
  -> build_permutations((2,))
    -> build_permutations(())
    <- build_permutations = [[]]
  <- build_permutations = [[2]]
...
<- build_permutations = [[1, 2], [2, 1]]
```

### Тесты и запуск

`permutations/test_permutations.py` проверяет примеры из условия, пустой и
одноэлементный вход, повторяющиеся и отрицательные значения, неизменность
исходного списка и фактическое подключение визуализации стека.

```bash
python -m homework_5.permutations.permutations
python -m unittest discover -s homework_5/permutations -p "test_*.py" -v
```

## Задача 3. AVL

### Корректность и идея решения

`AVL` — бинарное дерево поиска без повторяющихся ключей. Для каждой вершины
хранится высота. После рекурсивной вставки или удаления высота обновляется и
вычисляется разность высот левого и правого поддеревьев. Если её модуль стал
больше 1, выполняется одно из четырёх вращений: LL, RR, LR или RL. Вращения
сохраняют порядок бинарного дерева поиска и восстанавливают AVL-инвариант.

- `insert(key)` возвращает `True` для нового ключа и `False` для дубликата;
- `delete(key)` возвращает `True` для удалённого ключа и `False`, если его нет;
- `search(key)` возвращает признак присутствия;
- `inorder()` возвращает отсортированные ключи;
- `to_ascii()` визуализирует текущее дерево.

При удалении вершины с двумя детьми её ключ заменяется минимальным ключом
правого поддерева, после чего преемник удаляется рекурсивно.

### Оценка сложности

Высота AVL-дерева равна O(log n). Поиск, вставка и удаление проходят по одному
пути и занимают O(log n) времени. Вращение занимает O(1). Рекурсивный стек для
изменяющих операций требует O(log n) памяти; сами n вершин — O(n). Обход и
текстовая визуализация занимают O(n) времени и O(n) памяти результата.

### Пошаговая визуализация вращения

Последовательная вставка `30, 10, 20` создаёт случай LR:

```text
После 30, 10:      После вставки 20:    Левое у 10:      Правое у 30:

    30                  30                  30                 20
   /                   /                   /                  /  \
  10                  10                  20                 10  30
                        \                 /
                         20              10
```

Более полный пример после вставок `30, 20, 10, 25, 40, 50`:

```text
30
|-- L: 20
|   |-- L: 10
|   `-- R: 25
`-- R: 40
    `-- R: 50
```

После удаления алгоритм идёт обратно к корню, пересчитывая высоты и выполняя
такие же вращения при необходимости.

### Тесты и запуск

`AVL/test_avl.py` проверяет поиск и обход, все четыре вращения, дубликат,
удаление листа и вершин с одним и двумя детьми, балансировку после удаления,
пустое дерево, отсутствующий ключ, ASCII-визуализацию и серию из 200 вставок с
последующими удалениями. В тестах рекурсивно проверяются порядок ключей, высоты
и баланс каждой вершины.

```bash
python -m homework_5.AVL.avl
python -m unittest discover -s homework_5/AVL -p "test_*.py" -v
```
